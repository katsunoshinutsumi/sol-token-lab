# sol-token-lab（Solana devnet トークン学習用）

Solana の **devnet（テスト用ネットワーク。実際のお金は動かない）** で、テスト用トークンを
発行・送付・権限放棄し、草コインで問題になりやすい点をチェックするための学習用プロジェクトです。

- **devnet 専用**です。接続時にネットワークのジェネシスハッシュを確かめ、devnet 以外なら停止します。
- mainnet での発行・SOL の購入や送金・取引所/DEX への上場は、このプロジェクトでは扱いません。
- 投資判断や売買の助言を目的としたものではありません。

---

## 1. 準備

```bash
npm install
```

Node.js 20 以上を想定（動作確認は Node 24）。Solana CLI は不要です。

### 秘密鍵の扱い

| ファイル | 中身 | Git |
| --- | --- | --- |
| `.keys/devnet-wallet.json` | 練習用ウォレットの秘密鍵 | `.gitignore` で除外 |
| `.keys/recipient.json` | 送付先の練習用ウォレットの秘密鍵 | `.gitignore` で除外 |
| `.state/token-*.json` | 作ったトークンのミントアドレス等（公開情報） | `.gitignore` で除外 |

- 秘密鍵の中身はチャット・メール・スクリーンショットに貼らないでください。
- この鍵は PC 上に平文で置かれています。**mainnet の資産を入れるウォレットには使い回さない**でください。
- `git check-ignore -v .keys/devnet-wallet.json` で除外されていることを確認できます。

## 2. 手順（各ステップの意味）

| # | コマンド | 何をするか |
| --- | --- | --- |
| 1 | `npm run keygen` | devnet 用の鍵ペア（ウォレット）を作る。アドレスは公開してよい、秘密鍵は渡さない |
| 2 | `npm run airdrop` | 残高を確認し、テスト用 SOL を受け取る（下記の注意参照） |
| 3 | `npm run create` | Token-2022 でトークンを発行（名前・シンボル・小数点・総発行量・メタデータ） |
| 4 | `npm run check` | チェック用スクリプト。この時点では「発行権限・フリーズ権限が残っている」と出る |
| 5 | `npm run try-mint` | 発行権限が残っていると追加発行できてしまうことを体験（総供給量が 2 倍になる） |
| 6 | `npm run transfer` | 別アドレス（練習用の受取人）へ 1,000 枚送る |
| 7 | `npm run revoke` | 発行権限・フリーズ権限を放棄（`-- --metadata` でメタデータ更新権限も） |
| 8 | `npm run try-mint` | 今度は追加発行がチェーン側で拒否される |
| 9 | `npm run check` | 権限が放棄済みになったこと、保有の偏りを確認 |

従来の SPL Token で同じことを試す場合は、各コマンドに `-- --program token` を付けます
（例：`npm run create -- --program token`）。

トークンの名前・シンボル・小数点・総発行量は `token.config.json` で変えられます。

### テスト用 SOL の受け取り（本人の操作が必要）

2026 年時点で、公開 RPC（api.devnet.solana.com）からのエアドロップは閉鎖されており
`npm run airdrop` は「410 Gone」になります。次の手順で受け取ってください。

1. `npm run keygen` で表示されたアドレスをコピー
2. ブラウザで <https://faucet.solana.com> を開く
3. ネットワークが **devnet** になっていることを確認し、アドレスを貼り付けて受け取る
   （8 時間に 2 回まで。GitHub 連携で上限が上がります）
4. `npm run airdrop` で残高を確認（0.05 SOL 以上あれば練習には足ります。Token-2022・SPL Token の両方を一通り試して約 0.01 SOL でした）

**ページが動かないとき**：Chrome の自動翻訳がオンだと faucet のページが壊れ、ボタンを押しても送金されません
（開発者ツールに `removeChild` のエラーが出ます）。翻訳を切って英語のまま操作するか、シークレットウィンドウで開いてください。

devnet の SOL はテスト用で、売買できる価値はありません。

## 3. 用語と仕組み

- **ミント（mint）アカウント**：トークンの種類そのもの。小数点・総供給量・権限を保持。
  このアドレスがいわゆる「コントラクトアドレス（CA）」です。
- **トークンアカウント（ATA）**：誰がどのトークンをいくつ持つかを記録する口座。
  受取人が口座を持っていなければ送り手が作成費用（rent）を払って作ります。
- **小数点（decimals）**：チェーン上は整数で記録され、表示時に小数点をずらします。
  decimals=6 で「1 枚」はチェーン上 1,000,000。
- **発行権限（mint authority）**：追加発行できる権限。
- **フリーズ権限（freeze authority）**：特定の口座を凍結し、送金できなくする権限。
- **メタデータ更新権限**：名前・シンボル・画像 URL を書き換える権限。
- **rent**：アカウントをチェーン上に置いておくための預け金。容量に比例。

### SPL Token と Token-2022 の比較

| | SPL Token（従来） | Token-2022 |
| --- | --- | --- |
| プログラム ID | `Tokenkeg...` | `TokenzQd...` |
| 名前・画像 | ミントに置けない。Metaplex の Token Metadata で別アカウントを作るのが一般的 | 拡張機能（Metadata Pointer + Token Metadata）でミント自身に保持できる |
| 拡張機能 | なし | 送金手数料、永久委任、送金フック、譲渡不可、秘匿送金など |
| 対応状況 | ほぼすべてのウォレット・DEX が対応 | 主要ウォレットは対応。DEX やツールによっては一部の拡張に未対応 |
| 注意点 | 権限は発行・フリーズの 2 つを見ればよい | 拡張機能に**発行者が強い力を持つもの**があり、権限 2 つだけ見ても足りない |

本プロジェクトの従来 SPL Token 版はメタデータを付けていません（Metaplex 関連の依存を増やさないため）。
従来 SPL Token に名前・画像を付ける場合は Metaplex の `mpl-token-metadata` を使い、
その「更新可能（isMutable）」と更新権限も放棄対象として確認します。

## 4. 草コインでよく問題になる点と、このプロジェクトでの確認方法

`npm run check -- --mint <ミントアドレス>` で devnet 上の任意のトークンを確認できます。
結果は ✅（問題になりにくい設定）／⚠️（注意）／❌（重大）で表示されます。
**✅ だけでもそのトークンの価値や正当性を保証するものではありません。**

### 4-1. 発行権限を残したままの追加発行（希薄化）

- 「総発行量 10 億枚・追加発行なし」と宣伝していても、発行権限が残っていれば発行者は
  いつでも追加発行して売れます。既存保有者の持ち分は薄まり、価格は下がります。
- 確認：`check` の「発行権限」。体験：`try-mint`（放棄前は成功、放棄後は失敗）。
- 対策：配布が終わったら発行権限を放棄（`revoke`）。放棄は取り消せません。

### 4-2. フリーズ権限・Token-2022 拡張による「売れないトークン」

- フリーズ権限が残っていると、発行者が買った人の口座を凍結して売れなくできます
  （買えるが売れない「ハニーポット」型の詐欺で使われる手口）。
- Token-2022 では、永久委任（他人の口座からトークンを移せる）、送金フック（送金時に任意の処理）、
  送金手数料（率を後から上げられる場合がある）なども同様の効果を持ち得ます。
- 確認：`check` の「フリーズ権限」と「拡張」。

### 4-3. 流動性の引き上げ（ラグプル）

- DEX で売買できるようにするには、トークンと SOL をペアにして流動性プールに預けます。
  預けた人は **LP トークン**（またはポジション NFT）を受け取り、これを使うとプールの SOL を引き出せます。
- 発行者が LP を持ったままだと、買いが集まった後に SOL を全部引き出せます。残った買い手は
  売れない（売っても SOL がほぼ戻らない）状態になります。これがラグプルです。
- 確認：`check -- --mint <A> --lp-mint <LPミント>` で、LP トークンが焼却アドレス
  （`1nc1nerator1111...`）にあるか、特定の口座に偏っていないかを見ます。
- 限界：DEX の種類によっては LP トークンではなくポジション NFT や独自の口座で管理されるため、
  このスクリプトでは確認できません。ロック契約（一定期間引き出せない）の期限も別途確認が必要です。
  devnet には実用的な DEX のプールがほぼないため、この項目は主に考え方の確認用です。

### 4-4. 大口保有の偏り

- 発行者や少数のアドレスが大量に持っていると、まとめて売られたときに価格が崩れます。
  発行者が複数アドレスに分けて持つ（見かけ上分散させる）こともあります。
- 確認：`check` が上位 20 口座の割合を表示します（目安：最大口座 5% 超で注意・20% 超で強い偏り、
  上位 10 口座合計 25% 超で注意・50% 超で強い偏り）。
- 上位にプール・取引所・焼却アドレスがある場合は除いて判断します。持ち主アドレスを
  Explorer で開き、どういう口座か確かめてください。
- 自分で作った直後は自分が 100% を持っているので ❌ になります。これは想定どおりです。
- 公開 devnet RPC は上位保有者の取得（`getTokenLargestAccounts`）を強く回数制限しており、
  429 エラーになることが多いです。その場合は `.keys/` の練習用ウォレットと `--holders a,b,c` で
  指定したアドレスの残高だけを読む簡易版に切り替わります（全体像ではありません）。
  全体像を見たい場合は、Explorer の Holders 欄を見るか、別の devnet RPC を
  `SOLANA_RPC_URL` で指定してください（RPC 事業者の無料枠は登録が必要なことが多く、利用するかは本人判断）。

### 4-5. チェーンの外の問題（スクリプトでは確認できない）

- 有名人・有名プロジェクトのなりすまし、偽の提携発表、有料の宣伝を広告と明示しない宣伝
- 「必ず上がる」「○倍保証」などの約束、運営チームの匿名性、ホワイトペーパーの内容と実態の食い違い

## 5. mainnet で発行・販売・宣伝する前に確認すべきこと

> ここに書くのは**一般的な論点の整理**で、法的助言・税務助言ではありません。
> 実際に mainnet で発行・販売・宣伝する前に、**暗号資産に詳しい弁護士・税理士への確認を前提**としてください。
> 法令や運用は改正が続いている分野なので、確認時点の最新情報で判断してください（本 README は 2026 年 11 月時点の整理）。

### 5-1. 資金決済法（暗号資産・暗号資産交換業）

- 不特定の人と売買・交換でき、電子的に移転できるトークンは、資金決済法上の**暗号資産**に
  当たる可能性が高いです（ポイントのように発行者だけで使え、売買できないものとは扱いが違います）。
- 暗号資産の**売買・交換、その媒介、他人の暗号資産の管理を「業として」行う**には、
  暗号資産交換業の登録が必要です。**自分で発行したトークンを自分で不特定の人に販売する**
  （いわゆる ICO・セール・プレセール）ことも、これに当たり得ると整理されています。
- 無登録で行った場合は刑事罰の対象になり得ます。「海外の DEX で売るだけ」「SNS で告知するだけ」
  でも、日本居住者に向けた勧誘なら日本法の問題になり得ます。
- 暗号資産を金融商品取引法の枠組みに移す制度改正（インサイダー取引規制の導入など）が
  進められています。施行状況を確認してください。

### 5-2. 金融商品取引法（有価証券に当たらないか）

- 「売上の一部を保有者に分配」「収益に応じて配当」「運用益を還元」など、
  **他人の事業の収益を受け取る権利**が付くと、集団投資スキーム持分や
  電子記録移転有価証券表示権利等（いわゆるセキュリティトークン）に当たり得ます。
  その場合は金融商品取引業の登録や開示義務の対象です。
- 「保有者限定の特典」「買い戻しの約束」「最低価格の保証」なども論点になります。
  元本保証をうたって資金を集めることは出資法でも禁止されています。

### 5-3. 税金（日本の個人の場合の一般的な論点）

- 個人の暗号資産の売却益・他の暗号資産との交換益は、原則として**雑所得（総合課税）**です。
  事業として継続的に行う場合は事業所得になる可能性もあります。分離課税化の議論があるので、
  適用時期を確認してください。
- **暗号資産同士の交換、暗号資産での支払いも課税のタイミング**になります
  （例：自作トークンを売って SOL を受け取った時点）。
- 自分で発行したトークンの取得価額（ゼロか、発行費用か）、販売代金の所得区分、
  無償配布（エアドロップ）の扱いは、ケースごとに判断が分かれる論点です。
- 取引記録（日時・数量・相手アドレス・その時点の円換算額）は最初から全部残してください。
- **居住地**：海外に滞在している場合は、日本の居住者・非居住者の判定と、
  滞在国側の暗号資産規制・課税も確認対象です。どちらの国の法律が適用されるかは
  滞在形態・住所・生活の本拠などで変わります。
- 本業や他の事業の会計と混ぜないよう、口座・ウォレット・帳簿を分けてください。

### 5-4. 詐欺的と見られないための説明の仕方（一般的な整理）

最低限、次のことを**買う前の人が読める場所**に書くのが一般的です。

- 価格が上がる・利益が出るとは**約束しない**。「価値がゼロになり得る」「流動性がなく売れない
  ことがある」と明記する
- 総発行量と配分（運営保有・配布・プール投入の割合）、運営保有分の売却予定（ロック期間）
- 発行権限・フリーズ権限・メタデータ更新権限の状態（放棄済みかどうか、トランザクションへのリンク）
- 流動性プールの LP の扱い（焼却したか・ロックしたか・期限）
- 運営者が誰か、連絡先、ミントアドレス（偽物と区別できるように）
- 実用性（ユーティリティ）があるなら、実際にできることだけを書く。「予定」は予定と書く
- 有料で宣伝を頼む場合は広告であることを明示する（景品表示法のステルスマーケティング規制）
- 有名人・企業・他プロジェクトの名前やロゴを無断で使わない

### 5-5. 費用について（mainnet で実行する場合）

このプロジェクトでは mainnet での作業はしません。参考として、mainnet で行う場合に
本人の判断で確認すべき費用の種類だけ挙げます（金額は未確認・変動するため実行前に要確認）。

| 項目 | 内容 | 取り消し |
| --- | --- | --- |
| ミント・メタデータ作成の rent と手数料 | 少額の SOL。アカウントを閉じれば rent の一部は戻る場合がある | 作成自体は取り消せない |
| 流動性プール作成手数料 | DEX ごとに異なる | 取り消せない |
| プールに入れる SOL | 引き出しは可能だが、売買後は価格変動で目減りし得る。LP を焼却すると二度と戻らない | 焼却後は不可 |
| 権限の放棄 | 手数料のみ | **取り消せない** |
